# ONE COMMAND Cloud v1.2 | دليل التشغيل والحماية

## ما الجديد
- زر بدء الفحص يطلب فحوص Windows وONE ERP وOracle، دون إجراء أي تعديلات على بيانات ERP.
- لكل مهمة فحص حالة: في الانتظار، جارٍ التنفيذ، اكتملت، أُلغيت، أو انتهت مهلتها.
- يمنع النظام تكديس نفس نوع الفحص عدة مرات وهو قيد الانتظار أو التنفيذ.
- انتهاء جلسة الفحص أو الضغط على الإيقاف يلغي الطلبات غير المكتملة.
- مركز طلبات التطوير هو للتخطيط والمراجعة فقط، وليس مصادقة على تنفيذ تغييرات إنتاجية.
- نسخ طلبات التطوير تلقائيًا داخل هذا المتصفح فقط، مع زر «استعادة نسخة المتصفح» بعد إعادة تشغيل الاستضافة.
- تنزيل ملف JSON يدويًا واستعادة الطلبات على جهاز أو متصفح آخر.

## طريقة الاستخدام
1. افتح https://one-command-private-console.onrender.com وسجل الدخول بمفتاحك الخاص.
2. تأكد من ظهور وكيل Windows على أنه متصل.
3. اضغط «ابدأ التحكم والفحص» وانتظر اكتمال الفحوص في «حالة طابور الفحوص».
4. راجع «التشخيص التلقائي المجاني» والنتائج التفصيلية.
5. أضف طلبات التطوير إلى قائمة التخطيط، ولا تضع أسرارًا أو بيانات عملاء فيها.
6. نزّل نسخة JSON احتياطية دوريًا. إذا أعادت الاستضافة التشغيل وفقدت الطلبات، اضغط «استعادة نسخة المتصفح»، أو استعد ملف JSON.

## الحدود الحالية والمخاطر
- الموقع متاح على الإنترنت، لكن واجهات البيانات والمهام تتطلب تسجيل الدخول؛ لا توجد قائمة سماح IP أو تحقق ثنائي مفعّل حاليًا.
- مفتاح الدخول السابق ظهر في المحادثة، ويُوصى بتدويره من لوحة Render وتأمينه في مدير كلمات مرور.
- نسخة المتصفح المخزنة في LocalStorage غير مشفرة، ومقيدة بهذا المتصفح والجهاز. يمكن حذفها بمسح بيانات المتصفح، ولا تنتقل بين الأجهزة. استعملها لطلبات التخطيط غير الحساسة فقط.
- طلبات التطوير وسجل الفحوص على خادم Render لا تزال مؤقتة في الذاكرة؛ تخزين سحابي دائم يحتاج قاعدة بيانات مستقلة.
- الحالة «تمت المراجعة» لا تعني إطلاقًا السماح بتنفيذ تغيير. الفحوص الحالية قراءة فقط.
- فحص Oracle يتم عبر اتصال SSH مصرح به من وكيل Windows؛ لا يعني أن وكيل Desktop Commander على Oracle نفسه متصل.
- خدمة AI اختيارية وتتطلب مفتاح OpenAI API خاصًا بالمشروع. ChatGPT في المحادثة لا يتحكم في الموقع تلقائيًا.
- لا تدعم النسخة تشغيل أوامر نظام حرة، أو استعادة قواعد البيانات، أو تعديل فواتير وقيود ONE ERP.

## الأمان قبل تفعيل أي تعديل مستقبلي
نحتاج إلى قاعدة بيانات مستمرة مستقلة، تحقق ثنائي، فصل بين مهام الفحص والتنفيذ، موافقة محددة للخطوة المستهدفة، نسخ احتياطي قابل للاستعادة، اختبار تراجع، وسجل عمليات دائم.

هذه النسخة ليست نظام تحكم إنتاجي كامل.
